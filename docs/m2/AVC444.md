# AVC444 / AVC444v2 integration (2026-11-14)

## Runtime behavior

MacRemote has four graphics profiles: avc444, h264, balanced, and classic.
The AVC444 profile explicitly enables FreeRDP 3.33.1 settings
FreeRDP_GfxAVC444v2, FreeRDP_GfxAVC444, and FreeRDP_GfxH264;
RDPGFX progressive remains enabled as the non-H.264 fallback. The server
checks the actual RDPGFX capabilities advertised by the Windows client
and uses upstream AVC444v2/AVC444/AVC420 encoder dispatch. No custom
codec or RDP wire extension has been introduced.

The existing h264 profile remains AVC420-only, balanced remains progressive,
and classic remains bitmap-only. Saved graphics preferences are preserved.

Implementation and tests:
- src/graphics/rdp_graphics.c and src/graphics/rdp_graphics.h
- tests/test_graphics_modes.c (real FreeRDP capability flags)
- tests/test_avc444_encoder.c (real FreeRDP AVC444 codec)

## Encoding tests on Mac mini

A 128x128 colored BGRA frame was submitted to FreeRDP avc444_compress.
- AVC444 v1: rc=1, primary 4,121 bytes, auxiliary 10,378 bytes
- AVC444 v2: rc=1, primary 4,121 bytes, auxiliary 5,596 bytes
- Both frame region metadata sets populated; 11/11 CTests pass.

This confirms encoding, not successful Windows mstsc remote rendering.
A live Windows connection with the AVC444 graphics profile still needs
checking for sharp text, fast window movement, scrolling, resize,
reconnect and the older 0xD06 error.

## Activation

The currently connected Classic RDP session is left uninterrupted.
Build a new signed application using tools/build-dev-app.sh. When the
existing session is disconnected, install and launch the new App.
In the earlier experimental build, AVC444 was selected while stopped;
then start. Classic remains the stable compatibility option.

Upstream implementation:
https://github.com/FreeRDP/FreeRDP/blob/3.33.1/server/shadow/shadow_client.c
https://github.com/FreeRDP/FreeRDP/blob/3.33.1/libfreerdp/codec/h264.c


## 2026-11-14: Windows mstsc AVC444 failure and rollback

Current runtime: **Classic (stable)**. AVC444 remains experimental and is
**not yet validated** as a working Windows mstsc mode.

### Evidence from the failed Windows session

- Server running 3390 with AVC444 mode, PID 29322.
- A Windows LAN client connected, advertising RDPGFX capabilities 10.7/10.6.
- macOS capture surface changed from 1534x1066 to 2304x964 during startup.
- A second resize/deactivation/reactivation followed, then repeated client
  graphics capability advertisements and an RDPGFX channel read failure.
- Windows displayed scrambled graphics and a protocol error.
- The channel-read error shows the peer closed the channel; it does not
  identify the specific preceding Windows protocol violation.

### Source change and evidence

1. Reverted the speculative initial graphics size patch from the pinned
   FreeRDP tree and build script. It changed DesktopWidth/DesktopHeight
   inside ClientCapabilities after the initial negotiation, but did not
   prevent the resize and could cause inconsistent graphics dimensions.
   The failed patch was removed; the incident is retained in this report.
2. Added tests/test_avc444_roundtrip.c. Actual FreeRDP AVC444 v1/v2
   compression and decompression passed at 128x128, 1534x1066 and
   2304x964. This does not prove RDP packet compatibility or a successful
   client resize.
3. Added patches/freerdp-3.33.1-gfx-capability-diagnostics.patch to log
   the client-confirmed caps and sampled AVC444 codec/frame dimensions,
   payload sizes and version, only for failed-mode investigation.
4. Rebuilt and signed new MacRemote; 12/12 CTests passed; replaced installed
   app with a rollback copy retained.
5. Persisted graphicsMode=classic and restarted. Current GUI PID 34928,
   server PID 34935, IPv4/IPv6 3390 LISTEN.

Next experiment: use genuine Windows mstsc to retry the revised RDPGFX
pipeline with the speculative patch removed; compare AVC420 and AVC444
to isolate shared RDPGFX activation issues from AVC444-specific wire
format. Do not declare AVC444 fixed until real desktop rendering and
resize work. Keep Classic as the working default.

## Production UI decision (2026-11-14)

Following a real mstsc AVC444 protocol failure, MacRemote's normal
menu bar GUI was simplified to use verified Classic output exclusively.
Legacy graphicsMode, compatibilityGraphics and showMenuBarIcon
preferences are removed on GUI startup. AVC444, AVC420 and Progressive
remain diagnostic-only CLI options and have not completed real-client
acceptance. No production graphics selector or explanatory footnote.
